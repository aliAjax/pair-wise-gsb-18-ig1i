# hxwl-04 根尖手术看板：排程与术后随访

按牙位管理根尖手术的术前资料、显微镜排程与术后两周随访，替代纸表排期。

## 业务规则

- **牙位登记**：登记牙位、患者、诊断、术前影像日期、麻醉结论，新病例进入「待排」。
- **留待排条件**：术前影像距手术日期超过 30 天（过期，需重新拍片）或麻醉结论未确认，病例无法排程。
- **显微镜独占时段**：同一手术显微镜同一天同一时段（上午 08:30–12:00 / 下午 13:30–17:00）只接一台手术，冲突在选择时即时提示并在保存时拦截。
- **术后补录**：根尖切除长度、倒充材料、标本编号；标本编号全库唯一，重复即拦住。
- **两周复查分流**：术后第 14 天复查；疼痛未缓解或骨缺损增大 → 自动转入「复诊名单」，否则进入「复查通过」。

看板五列：待排 → 已排程 → 已手术 →（复查通过 / 复诊名单）。

## 分层结构（资料、判断、保存、界面分开）

```
src/
  domain/            资料层 + 判断层（与 React、存储无关的纯 TypeScript）
    types.ts         数据结构：病例、排程、术后记录、复查记录
    dates.ts         本地时区日期工具（YYYY-MM-DD）
    rules.ts         纯判断：影像时效、排程资格、时段冲突、标本唯一、复查分流
    seed.ts          示例数据
  storage/
    repository.ts    保存层：localStorage 仓储（可替换为后端 API）
  application/
    useCases.ts      用例编排：登记/排程/退排/术后补录/复查
    selectors.ts     看板派生：分列、指标、留滞原因
  ui/                界面层：看板、卡片、表单、弹窗、显微镜时段表
```

业务规则全部集中在 `src/domain/rules.ts` 的纯函数中，`scripts/smoke-rules.ts` 覆盖 18 条规则断言。

## 本地运行

```bash
npm install
npm run dev          # http://localhost:5104
npm run build        # 类型检查 + 生产构建
npm run test:rules   # 业务规则冒烟测试
```

数据保存在浏览器 localStorage（键：`apico-board:cases:v1`），界面上可一键恢复示例数据。
